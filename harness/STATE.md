- `command_policy.py`: валидация argv, независимые правила, явный порядок
  запреты → согласование → точный allowlist; неизвестная команда получает `ask`.
- `runtime.py`: проверка перед исполнителем, неизменяемые сохранённые argv и
  абсолютная cwd; одноразовые `confirm(request_id)` и `reject(request_id)`.
  Запреты проверяются повторно. Запрос потребляется под Lock до выполнения;
  это не гарантия exactly-once при сбое внешней системы.
- `RecordingExecutor` записывает команды и директории только в память.
  Реальные процессы, Docker, API и БД не вызываются.
- Runtime ограничивает вызовы исполнителя через `max_executions` (по умолчанию 3).
  Атомарное резервирование под Lock; ошибка расходует слот, deny/ожидание/отказ — нет.
  Подтверждение не обходит бюджет. Исчерпание отражается отдельным полем результата
  и событием `execution_limit_reached`, а не запретом политики. Лимит действует
  на экземпляр; постоянных квот, лимитов запросов/токенов/времени пока нет.
- `events.py`: события в памяти, общий operation_id, решения и длительность
  вызова исполнителя; ошибки записываются по типу без текста. CLI выводит трассу.
  События не содержат argv/cwd/output. Нет постоянного хранения, ограничения
  количества событий или полного аудита инфраструктурных ошибок.
- `cli.py`: JSON-список аргументов, решение политики, сохранённая операция,
  явное согласие/отказ. Запуск из корня: `.\.venv\Scripts\python.exe -m harness.cli`.
- Подтверждения хранятся только в памяти экземпляра. Нет TTL, постоянного
  хранения, аутентификации и проверки владельца; пример однопользовательский.
- 8 октября пользователь подтвердил блокировку демонстрационной команды проектным hook
  в CLI и VS Code. После проверки конфигурация переименована в
  `.codex/hooks.disabled.json`; на тот момент активный `.codex/hooks.json`
  отсутствовал. Это не описание текущего состояния второго hook.
  `confirm` предназначен доверенному интерфейсу человека, не инструменту модели.
- Skill ревью: `.agents/skills/review-changes/SKILL.md`. Делегированное ревью
  subagent продемонстрировано: это возможность coding-среды, не CommandRuntime.
