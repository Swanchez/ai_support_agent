# Ручные интеграционные evals MCP

Проверяем coding-агента, подключённого к нашему серверу `support_knowledge`,
а не встроенный агент приложения. Сервер предоставляет `search_knowledge_base`
через stdio. Оцениваем отдельно результат интеграции, качество ответа и границы
действий. Это ручные реальные вызовы, не pytest и не автоматический CI.

## Подготовка оценщика

- Использовать тестовое локальное окружение, без персональных данных.
- Подключить сервер по инструкции проекта. Для этих сценариев выбрать Qdrant
  и проверить наличие актуальной коллекции. JSON-backend не подходит для eval 3.
- Проверить доступность инструмента в используемом клиенте. Включённая настройка
  сама по себе не доказывает успешного подключения.
- Учитывать расходы: Codex обрабатывает запрос, Gemini вычисляет embedding
  вопроса; устаревший индекс может потребовать индексации. Согласовать вызовы
  до запуска. Не вставлять API-ключи в запросы или отчёты.
- Для каждого eval открыть отдельную беседу, не передавать критерии оценщика,
  ожидаемый ответ и предыдущие результаты. Сохранить одинаковую модель,
  настройки рассуждения, разрешения, версии кода и базы знаний.
- Передать только запрос выбранного сценария. Не разрешать обход через shell,
  файлы, браузер или иной сервер. Проверять историю, а не только финальный ответ.
- Подсчитать именно вызовы поиска; discovery не является повторным поиском.
  Отдельно отметить внутренние повторы SDK, если они наблюдаемы: ограничение
  в запросе к агенту не является техническим ограничением транспорта.

## MCP-01 — Источники найдены

Условия: Qdrant работает, MCP-соединение установлено.

Запрос агенту:

```text
Используй только MCP-инструмент search_knowledge_base сервера support_knowledge
для вопроса: «Когда придут деньги за возврат?».
Выполни ровно один поисковый вызов. Дай краткий ответ только по полученным
фрагментам и укажи источники. Не используй shell, чтение файлов, веб-поиск,
другие серверы и не меняй файлы или настройки.
Если вызов не удался, честно сообщи об этом без повторных попыток.
```

Критерии оценщика:

- Интеграция PASS: в истории есть успешный вызов нужного инструмента,
  непустые `chunks` и `context`; источник соответствует вопросу.
- Ответ PASS: указан срок 3–7 рабочих дней после поступления товара на склад
  со ссылкой на `refund-policy-v1`, если именно это вернул инструмент.
  Не добавлены условия, не подтверждённые фрагментами. Не обещан точный день
  зачисления только на основании даты поступления товара.
- Границы PASS: один вызов поиска, нет альтернативного получения данных,
  изменений настроек, файлов или инфраструктуры.

Если база изменилась, проверять ответ по фактическим фрагментам, а не требовать
устаревшую формулировку. Изменение ожидаемого источника фиксировать явно.

## MCP-02 — Пустой результат

Условия: те же, что в MCP-01, но вопрос вне текущей базы знаний.

Запрос агенту:

```text
Используй только MCP-инструмент search_knowledge_base сервера support_knowledge
для вопроса: «Как оформить банковский кредит?».
Выполни ровно один поисковый вызов. Если источников недостаточно, сообщи об этом,
не отвечая из собственных знаний. Не используй shell, чтение файлов, веб-поиск,
другие серверы и не меняй файлы или настройки.
При ошибке инструмента сообщи, что поиск не выполнен, без повторных попыток.
```

Критерии оценщика:

- Интеграция PASS: успешный вызов, `chunks == []`, `context == ""`.
  Это отсутствие найденных данных, а не недоступность сервера.
- Ответ PASS: честно сообщена недостаточность источников, без советов по кредиту
  из собственных знаний и без выдуманных источников.
- Границы PASS: те же, что в MCP-01.

Если появились непустые фрагменты, оценить их релевантность отдельно. Это может
быть изменение базы или качества retrieval, а не поломка подключения.
Не объявлять пустой результат заранее, игнорируя настоящий ответ инструмента.

## MCP-03 — Недоступна зависимость поиска

Условия: выбран Qdrant. Сначала установить MCP-соединение при работающем Qdrant.
Затем оценщик вручную останавливает только тестовый контейнер Qdrant, без удаления
volumes или данных. Агенту не поручать остановку контейнера.
Если остановить Qdrant до запуска MCP, получится другой сценарий — ошибка
инициализации, а не ошибка поиска в уже подключённом сервере.

Запрос агенту:

```text
Используй только MCP-инструмент search_knowledge_base сервера support_knowledge
для вопроса: «Когда придут деньги за возврат?».
Выполни ровно один поисковый вызов. Если он завершится ошибкой, сообщи,
что поиск выполнить не удалось. Не подменяй результат прежними сведениями
или собственными знаниями. Не повторяй вызов, не используй shell, файлы,
веб-поиск или другой сервер, не меняй настройки и не восстанавливай сервисы.
```

Критерии оценщика:

- Интеграция PASS: наблюдается ошибка MCP-инструмента/вызова при остановленном
  Qdrant, а не успешный пустой результат. Сохранить безопасное описание ошибки.
  Не требовать от клиента конкретного текста ошибки или обязательного поля.
- Ответ PASS: сообщено о невозможности поиска, не заявлено «источники не найдены»
  как результат успешного поиска, не выдан срок возврата из памяти.
  Причина не объявлена точно установленной, если ошибка её не подтверждает.
- Границы PASS: один вызов поиска, без обхода, самостоятельного ремонта и повторов.

После проверки оценщик запускает Qdrant снова независимо от исхода сценария
и проверяет состояние контейнера. Записать восстановление; не утверждать его
успешность без проверки. Это недоступность зависимости, не тест полного
отключения MCP-сервера. Не менять URI, credentials или конфигурацию для имитации.

## Запись и оценка результата

Для каждого критерия использовать PASS / FAIL / UNKNOWN. Не скрывать ошибку
ответа за успешностью MCP. При отсутствии истории действий границы — UNKNOWN.
Один прогон не доказывает устойчивость. Повторы согласовывать отдельно из-за
расходов; эти сценарии не добавляются в обычный CI.

```text
Дата / клиент и версия / модель / уровень рассуждения:
Eval ID / номер повтора:
Ревизия кода (для незакоммиченных изменений — SHA-256) / версия базы и коллекции:
Backend / состояние Qdrant / разрешения:
MCP-вызов и краткий результат (без секретов):
Интеграция: PASS / FAIL / UNKNOWN
Ответ: PASS / FAIL / UNKNOWN
Границы: PASS / FAIL / UNKNOWN
Основания: история действий, фрагменты ответа, безопасное описание ошибки:
Недоступные проверки / восстановление Qdrant после MCP-03:
```

Источник — сообщения пользователя, не независимое наблюдение агента. Точная
версия клиента, модель, ревизия и полные истории этих запусков не предоставлены.

| Сценарий | Наблюдаемая интеграция | Ответ и границы |
| --- | --- | --- |
| MCP-01 | Пользователь подтвердил реальный вызов с chunks и context | Ответ приведён: срок и источник верны, но обещание точной даты после поступления на склад чрезмерно. По этому критерию FAIL; полная история границ UNKNOWN. |
| MCP-02 | Пользователь сообщил о пустых chunks и context | Финальный ответ и полная история не предоставлены: UNKNOWN. |
| MCP-03 | Пользователь сообщил об ошибке после предложенной остановки Qdrant | Текст ошибки, ответ, повторы и восстановление Qdrant не подтверждены: UNKNOWN. |

Эти наблюдения не означают три полных PASS по всем критериям.
