# Проверка файлов перед apply_patch

`protect_files.py` получает JSON события PreToolUse через stdin, проверяет
`tool_input.command` и возвращает JSON. Не применяет patch, не читает содержимое
файлов и не изменяет их. Использует метаданные путей для проверки symlinks.
Контракт Codex: https://learn.chatgpt.com/docs/hooks

Обработчик блокирует операции с `.env` и `protected-demo.txt` (включая вложенные
пути и различия регистра). `.env.example` допускается. При перемещении проверяются
исходный и конечный пути; защищённая операция блокирует весь patch. Пустой ответ
`{}` оставляет штатные разрешения Codex, а не разрешает обход sandbox.

Это узкий учебный разбор стандартного apply_patch, не полный парсер всех его
форматов. Неизвестный формат, пути с `..`, выход за cwd, альтернативные потоки
Windows и неоднозначные пути отклоняются. Абсолютные пути допускаются внутри cwd.
Разбор не исполняет строки patch как команды. В ответ не включаются пути,
содержимое patch и текст исключения.

## Локальная проверка

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider harness/tests/test_protect_files.py
```

Тесты передают искусственные события; временные файлы содержат только тестовые
данные. Они проверяют операции, перемещение, неоднозначные пути, протокол stdin
и отсутствие содержимого patch в ответе. Тест symlink может быть пропущен, если
платформа не разрешает его создание. Реальный `.env` не используется.

## Подключение отдельно от проверки обработчика

`protect-files.example.json` — неактивный шаблон. Подставить абсолютные пути
Python и скрипта. Windows-команда предполагает PowerShell. Не включать без
согласования и не заменять существующие группы hooks. После подключения через
штатную процедуру доверия проверить фактический клиент и версию.

Для интеграционного теста создать отдельную временную папку без секретов,
с файлами `normal.txt` и `protected-demo.txt`, содержащими строку `before`.
Попросить coding-агента через apply_patch заменить её на `after`: сначала
только в normal.txt, затем отдельным вызовом только в protected-demo.txt.
Проверить историю hook и содержимое: обычный файл изменился, защищённый остался
прежним, второй вызов получил HARNESS_PROTECTED_FILE до записи. Не пытаться
обойти отказ другим инструментом. После демонстрации отключить только новую
группу, сохранив чужие hooks. Не активировать первый строгий Bash-hook вместе
с этой демонстрацией без необходимости.

## Ограничения

Shell и другие инструменты записи не перехватываются этим matcher. Защищаются
только перечисленные имена: это не универсальная защита всех секретов.
Остаются ограничения Windows aliases, hard links и гонки изменения файловой
системы между проверкой и применением. Ошибка запуска Python или timeout hook
может не заблокировать вызов. Нужны sandbox и права файловой системы.

Создание обработчика и локальные unit-тесты не доказывают, что расширение
загрузило hook. Конфигурация в этом шаге не активирована.
