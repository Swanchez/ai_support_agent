# Адаптер PreToolUse — проверен, временная конфигурация отключена

Официальный контракт: https://learn.chatgpt.com/docs/hooks

`pre_tool_use.py` читает событие JSON из stdin, возвращает только служебный JSON
в stdout. Ничего не выполняет и не использует CommandRuntime, его бюджет или
confirm. JSON deny блокирует поддерживаемый вызов инструмента; пустой JSON
не вмешивается в штатные проверки Codex. Это не обход sandbox/approvals.

Разрешены только точные строки `git status --short` и `docker compose ps`:
они сопоставляются с argv и проверяются общей политикой. Не используем split,
strip или исполнение shell для разбора. Все другие строки и некорректные события
получают deny. `echo HARNESS_BLOCK_DEMO` — отдельная безопасная проверка отказа.
Ни переданная команда, ни её секреты не включаются в ответ обработчика.

## Проверка без подключения

Из корня проекта в PowerShell:

```powershell
Get-Content harness/hooks/blocked_event.json -Raw -Encoding UTF8 | .\.venv\Scripts\python.exe -B harness/hooks/pre_tool_use.py
```

Ожидается JSON с `permissionDecision: "deny"` и причиной HARNESS_BLOCK_DEMO.
Это проверка протокола обработчика; не доказательство, что Codex его загрузил.

## Подключение — отдельный согласованный шаг

`hooks.example.json` — неактивный шаблон, а не действующая настройка.
Перед включением проверить используемый клиент/версию Codex и его поддержку hooks.
Заменить placeholders абсолютными путями к Python виртуального окружения и
`harness/hooks/pre_tool_use.py`. Windows-строка предполагает PowerShell;
запуск команды нужно проверить в фактической среде клиента, без ослабления прав.
При другом shell потребуется его корректное quoting.

После согласования объединить конфигурацию с существующей (не перезаписывать её)
в `<repo>/.codex/hooks.json` либо inline hooks в config.toml. Не создавать обе
формы одновременно. Проект должен быть открыт именно как репозиторий,
его конфигурация/обработчик — просмотрены и доверены через поддерживаемый UI.
Не обходить проверку доверия. При необходимости начать новую сессию клиента.

Затем попросить агента вызвать `git status --short` и отдельно
`echo HARNESS_BLOCK_DEMO`. Первая команда должна пройти, вторая остановиться
до исполнения с причиной hook. Проверить историю событий, а не только финальный
текст ответа. Не заменять демонстрацию опасной операцией с данными.

## Ограничения и отключение

- Этот строгий allowlist блокирует почти все обычные shell-команды, включая
  pytest и чтение файлов через PowerShell. Включать только для короткой проверки.
- В конфигурации matcher `^Bash$`: это имя hook для shell/unified exec Codex,
  не требование запускать bash.exe на Windows. Не перехватывает все инструменты,
  например apply_patch и hosted web search. Нет полной границы безопасности.
- `ask` для PreToolUse не поддержан текущей документацией. Не возвращаем его:
  запросы, требующие согласования, здесь блокируются, а не открывают наш CLI.
- Обработанные ошибки входа превращаются в явный deny. Но ошибка запуска Python,
  импорта, timeout или ошибка самого hook могут не остановить вызов Codex.
  Текстовая политика fail closed не гарантирует fail closed всей среды.
- Нет долговременного аудита, глобального бюджета, контроля PATH, executable,
  конфигурации Git/Docker и полной проверки cwd. Даже точная команда требует
  доверенного окружения и sandbox.
- Для отключения удалить только добавленную группу PreToolUse из активной
  конфигурации, сохранив чужие hooks. Не удалять весь config и не отключать sandbox.
